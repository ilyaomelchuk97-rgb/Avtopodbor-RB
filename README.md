# MOTOR.BY — автомобильный агрегатор по Беларуси

Готовый к размещению **Render Web Service** без API-ключей. Backend получает реальные объявления и складские карточки из публичных каналов источников, приводит их к единой структуре, а frontend показывает автомобили непосредственно на сайте в адаптивном премиальном интерфейсе с тёмной и светлой liquid-glass темами.

**Текущая сборка: `1.10.0`.**

## Подключённые источники

1. **Onlíner Автобарахолка** — поиск, фильтры, полная карточка, комментарий продавца, оснащение, галерея и изображения поколений.
2. **Kufar Авто** — SSR-каталог, фильтры, cursor-пагинация, полная карточка, описание продавца и настоящие фотографии.
3. **AV.BY** — публичный мобильный каталог: поиск, фильтры, города/области, полная карточка, оснащение и фотографии `avcdn.av.by`.
4. **Дилеры** — объединённая выдача склада новых автомобилей Атлант-М и компаний/автосалонов AV.BY со всей Беларуси: реальные цены, фотографии, комплектации, статусы, адреса и продавцы.
5. **Автохаусы** — объединённая выдача «Атлант-М Автомобили с пробегом» и business-объявлений автохаусов/автосалонов AV.BY по всей Беларуси.

### Устойчивый транспорт Onlíner на Render

Некоторые исходящие IP-адреса Render не устанавливают соединение с Onlíner, хотя сам публичный каталог работает. Backend сначала проверяет прямой маршрут с коротким тайм-аутом, а при сетевой ошибке переключается на ограниченный keyless relay Jina Reader. Relay возвращает тот же публичный JSON Onlíner; приложение заново проверяет формат и нормализует только реальные объявления. Подмена демонстрационными карточками не выполняется: ответы сохраняют `live: true`, `mock: false`, а при отказе обоих маршрутов источник получает явный статус ошибки.

Успешный прямой маршрут или relay кэшируется обычным TTL, а неудачный прямой маршрут запоминается на пять минут, чтобы каждый поиск не ждал повторного сетевого тайм-аута. Поле `onliner.transport` в `GET /api/health` показывает `direct` либо `reader`; поиск, полная карточка, описания и справочники используют один и тот же безопасный fallback без API-ключа.

«Дилеры» и «Автохаусы» являются отдельными переключателями и одновременно участвуют в общей выдаче. Конкретная компания и каталог явно указаны в каждой карточке, например:

- `Дилеры · Атлант-М` / `Новые автомобили официальных дилеров`;
- `Дилер · MinskAuto` / `Новые автомобили компаний AV.BY по Беларуси`;
- `Автохаус · Атлант-М` / `Атлант-М Автомобили с пробегом`;
- `Автохаус · Автосалон «БелАвтоМаркет»` / `Автомобили с пробегом компаний AV.BY по Беларуси`.

Справочник марок и моделей объединяет taxonomy Onlíner со складскими каталогами дилеров и автохауса, поэтому новые дилерские марки/модели не исчезают из фильтра. Поколения Onlíner содержат годы и каталожные изображения; в выпадающем выборе модели счётчик поколений не показывается. Для модели, у которой источник не публикует поколения, интерфейс не рисует фиктивные варианты.

Множественный выбор поколений передаётся источникам как единый OR-фильтр: повторяемые generation ID у Onlíner, `v.or` у Kufar и несколько блоков `brands` у AV.BY. Business-объявления AV.BY фильтруются его нативной taxonomy, а складские записи Атлант-М проверяются по detail-карточкам, поэтому выдача не расширяется до неподходящих поколений.

Для одного поколения во всех карточках выдачи используется одна каноническая фотография из каталога поколений, а не меняющаяся фотография объявления. Названия шасси разных площадок (`G20/G21` ↔ `G2x`, `F30/F31` ↔ `F3x`) сопоставляются с учётом рестайлинга и года; та же фотография сохраняется после загрузки detail-карточки.

Фильтр коробки **«Автомат + робот»** объединяет классические автоматы и роботизированные коробки одним поиском. Для AV.BY используются нативные значения `1 + 3`, для Kufar — основной автоматический класс с подтипами `Автомат + Робот`, для Атлант-М — `AUTOMATIC + ROBOT + DSG`; Onlíner публикует робот внутри своего общего класса `automatic`. Механика остаётся отдельной.

## Сквозная сортировка и пагинация

Сортировка больше не применяется отдельно к каждой видимой странице. При поиске frontend собирает доступные страницы источников (до пяти страниц каждого каталога), удаляет дубли, формирует **один общий набор**, сортирует его и только после этого делит по 12 карточек. Поэтому последняя цена на странице 1 и первая цена на странице 2 продолжают один возрастающий или убывающий ряд; тот же принцип действует для года и пробега.

Onlíner, Kufar и AV.BY получают нативный параметр сортировки уже при запросе, чтобы в доступную выборку попадал нужный край каталога: дешёвые, дорогие, новые/старые по году или автомобили с меньшим пробегом. После объединения frontend повторно применяет единый детерминированный comparator с датой и ID как стабильными дополнительными ключами.

Под карточками находится обычная пагинация **«Назад / номера страниц / Вперёд»**. Можно сразу выбрать конкретную страницу; текущая страница и диапазон показанных автомобилей подписаны. Переход не делает новый разрозненный поиск, поэтому выбранная сортировка не сбрасывается и порядок не начинается заново. Сортировка сохраняется в IndexedDB и в URL сохранённого поиска, а номер открытой страницы записывается в `resultPage` и восстанавливается после обновления вкладки.

## Цена BYN / USD

Над диапазоном цены находится постоянно видимый переключатель **BYN / USD**. При переключении уже введённые пределы конвертируются в обе стороны, а подпись показывает используемый официальный курс. Frontend всегда отправляет источникам нормализованные `priceFrom` / `priceTo` в BYN, поэтому Onlíner, Kufar, AV.BY, дилеры и автохаусы продолжают получать одну и ту же валюту независимо от представления формы.

При каждом открытии сайта курс проверяется автоматически. Все долларовые эквиваленты в карточках и таблице сравнения заново рассчитываются из актуальной цены BYN и помечаются **«НБРБ»**, а не копируют потенциально устаревшую USD-сумму площадки. Пока вкладка открыта, проверка повторяется раз в час и после возврата в давно неактивную вкладку. Если у объявления нет цены BYN, сохраняется опубликованная источником USD-сумма как резерв.

Курс получает собственный keyless endpoint `GET /api/exchange`. Backend запрашивает официальный публичный API НБРБ `https://api.nbrb.by/exrates/rates/431`, учитывает `Cur_Scale`, кэширует результат на один час и может использовать свежую кэшированную копию до семи суток при временном сбое НБРБ. Если официальная копия ещё не была получена, endpoint честно возвращает `live: false` и обозначенный резервный курс; API-ключи не нужны.

Deep link хранит выбранную `priceCurrency`, исходные `priceDisplayFrom` / `priceDisplayTo` для USD и нормализованные BYN-пределы. Поэтому получатель ссылки видит те же числа и валюту, а новый поиск снова выполняется по BYN с актуальным курсом.

## Поделиться подборкой и сравнить автомобили

В панели результатов есть кнопка **«Поделиться»**. Она формирует deep link текущих источников, режима, марки, модели, нескольких поколений, всех фильтров, цены и валюты, сортировки и открытой страницы. На поддерживаемых телефонах используется системный Web Share; в остальных браузерах ссылка копируется в буфер обмена. Никакой аккаунт или внешний сервис для ссылки не требуется.

Кнопка **«Сравнить»** рядом с названием карточки добавляет автомобиль в локальную подборку. Одновременно можно выбрать до трёх автомобилей. Постоянная нижняя панель показывает выбранные машины и открывает адаптивную таблицу с ценой в BYN/USD, годом, пробегом, двигателем и мощностью, коробкой, кузовом, приводом, топливом, поколением, модификацией, местом, продавцом, источником и ссылкой на оригинал. Лучшие числовые значения выделяются; на телефоне первый столбец закреплён, а автомобили прокручиваются горизонтально.

Без входа снимки сравнения хранятся в `localStorage`; после Google-входа они также входят в приватную облачную копию аккаунта. Выбор переживает новый поиск и перезагрузку, обновляется при повторном получении объявления и удаляется кнопками в панели или таблице. Максимум три позиции защищает интерфейс от тяжёлой широкой таблицы. VIN в сравнение и облачную копию не включён, и существующий VIN-модуль релизом `1.10.0` не изменялся.

## Режим карточек со свайпом

Справа от заголовка **«Свежие объявления: n»** находится квадратная кнопка с иконкой карточек. Она открывает полноэкранный режим выбора автомобилей из всей текущей живой, отфильтрованной и отсортированной выдачи — не только из видимой страницы. Влево объявление пропускается, вправо добавляется в существующее **Избранное**. Те же действия доступны явными нижними кнопками, а на клавиатуре — стрелками `←` / `→`; `Escape` закрывает режим.

Карточка показывает реальную фотографию объявления, цену BYN и пересчитанную цену USD по НБРБ, характеристики, поколение, комментарий, место и ссылку на оригинал. Следующие фотографии начинают подготавливаться только после явного открытия режима. Выбранное справа сохраняется тем же локальным/облачным механизмом, что и сердце в обычной выдаче. В офлайн-режиме, личной ленте избранного и при пустом результате кнопка недоступна; демонстрационные автомобили не подставляются.

## Персональная 3D-фотомодель каждого автомобиля

В каждой карточке находится кнопка **«3D по фото»**. После нажатия frontend берёт до восьми реальных фотографий именно этого объявления и размещает их как отдельные ракурсы в интерактивной CSS 3D-сцене. Поэтому у каждого автомобиля собственная фотомодель с его цветом, кузовом, дисками, повреждениями и комплектацией на опубликованных продавцом снимках — общие демонстрационные GLB больше не используются.

Фотомодель вращается мышкой или одним пальцем, масштабируется колесом или щипком, поддерживает выбор конкретного ракурса и сброс камеры. Автовращения и декоративных анимаций нет. Остальные фотографии автомобиля не запрашиваются ради 3D до явного нажатия кнопки; внешняя 3D-библиотека, WebAssembly, API-ключ и GPU-модель не нужны.

Панели образуют правильную многогранную сцену: радиус вычисляется из фактической ширины кадра и количества ракурсов, стандартные отступы `figure` обнулены, а субпиксельный нахлёст закрывает щели на гранях. При изменении размера окна геометрия пересчитывается через `ResizeObserver`. На iPhone 13 mini заголовок, сцена, кнопки ракурсов, пояснение и ссылка полностью помещаются в экран `375 × 812`, а сброс камеры превращается в компактную иконку.

Один или несколько обычных снимков математически не содержат достоверной геометрии скрытых частей автомобиля. Поэтому интерфейс честно называет результат **пространственным фотопросмотром**, а не выдумывает форму невидимой стороны. Ссылка под сценой всегда ведёт к оригиналу фотографий на площадке.

## Надёжная доставка фотографий

Фотографии объявлений AV.BY (`avcdn.av.by`), Onlíner (`imgproxy.onliner.by`) и изображения поколений Onlíner (`content.onliner.by`) загружаются напрямую в браузере с политикой `no-referrer`. Это обходит исходящие IP Render, которым CDN площадок отвечает `423` либо сетевым тайм-аутом. Service Worker больше не перехватывает внешние marketplace-изображения и не пытается сохранять opaque-ответы в Cache API — именно такой сбой мог превращать успешно полученное фото в пустую карточку, особенно в Safari. Новая версия Worker активируется сразу и один раз перезагружает вкладку, поэтому старый обработчик не остаётся до полного закрытия браузера. Локальные изображения интерфейса продолжают кэшироваться.

## Рыночная шкала цены

Справа от цены каждой карточки находится цветная шкала **от минимальной до максимальной цены** сопоставимых автомобилей. Белый маркер показывает место текущего объявления, а подпись классифицирует его как **«Низкая цена»**, **«Средняя по рынку»** или **«Высокая цена»**. Число рядом со словом «Рынок» показывает фактический размер выборки.

Сначала расчёт использует реальные автомобили текущей выдачи. Если для марки и модели совпадений недостаточно, frontend ставит карточки рядом с viewport в ограниченную очередь запросов `/api/market`: backend без API-ключей получает до 64 дополнительных объявлений с двух страниц Onlíner/Kufar и кэширует компактную выборку на 20 минут. Сопоставляются марка, модель и состояние (новый/с пробегом); при наличии минимум двух совпадений используется то же поколение, а при наличии минимум трёх — близкие годы выпуска `±3`. После догрузки диапазон обновляется прямо в карточке.

Если даже дополнительная живая выборка не дала двух сопоставимых автомобилей, интерфейс больше не оставляет частое состояние «Мало данных»: маркер остаётся по центру, выводится **«Средняя цена»**, а цена самого объявления обозначается как **ориентир**, не как подтверждённая статистика. Реальные min/max и классификация low/mid/high показываются только там, где выборка действительно доступна.

## Статичный Showroom и быстрый интерфейс

Hero сохраняет автомобильную сцену и отдельные фотографии для тёмной и светлой тем, но теперь полностью статичен. Удалены параллакс, перспективная сетка, линия горизонта, дублированное отражение автомобиля и постоянно движущиеся прожекторы. Остались только два лёгких радиальных световых пятна без CSS blur, один компактный showroom-индикатор и три подтверждения под описанием.

Карточка сохраняет новую иерархию: название отделено от общей панели цены и рыночной шкалы, шесть характеристик оформлены техническими плитками, поколение вынесено в отдельную панель, комментарий продавца — в цитату. Цвет площадки теперь используется строго и ровно: точка в бейдже, прямая двухпиксельная линия сверху карточки, нижняя граница фотографии и вертикальная граница комментария. Искажённые боковые световые линии и широкое цветное свечение удалены.

- **AV.BY — синий** `#218cff`;
- **Onlíner — красный** `#f0444c`;
- **Kufar — зелёный** `#18c879`;
- дилеры сохраняют фиолетовый, автохаусы — бирюзовый.

В CSS больше нет `@keyframes`, `animation` и `transition`. Удалены каскадное появление карточек, импульс пагинации, анимированный skeleton, подсказка свайпа, анимации панелей, hover-zoom и плавная программная прокрутка. Все состояния переключаются мгновенно, а загрузка обозначается статичными skeleton-плитками и кольцами.

## Темы и облегчённое стекло

В шапке постоянно виден отдельный двухпозиционный выбор **«Тёмная / Светлая»**. Выбор записывается в IndexedDB и зеркалируется в `localStorage`, а `theme-color` браузера обновляется динамически. Светлая тема использует голубой/синий акцент, отдельную hero-фотографию `assets/hero-car-light.jpg` и собственный абстрактный фон.

Для устранения рывков `backdrop-filter` полностью отключён в основном поиске, фиксированной шапке, выдаче, пагинации, меню кузова, lightbox и личной панели. Повторяемые карточки, технические плитки, поколения и комментарии также больше не используют SVG `feDisplacementMap`. Стеклянный вид формируется статичными полупрозрачными заливками, ровными границами и внутренними бликами, поэтому движущийся под интерфейсом контент не требует повторной растеризации. VIN-модуль при этом не изменялся.

Все карточки изолируют внутреннюю отрисовку через `contain: paint`. На планшетах и телефонах карточки ниже viewport дополнительно пропускают layout/paint через `content-visibility: auto` и получают адаптивный `contain-intrinsic-size`, поэтому браузер не растеризует всю длинную одноколоночную страницу заранее. Hover больше не меняет тени карточки при прохождении контента под неподвижным курсором. Декодированный image-cache уменьшен с 36 фотографий до 12 на desktop и 8 на телефоне. Фоновая подгрузка соседних фотографий при обычной прокрутке отключена: два соседних кадра запрашиваются только после явного взаимодействия с галереей или lightbox. Зоны раннего запуска detail-запросов и рыночной выборки сокращены до 200–250 px. Это уменьшает одновременно расход памяти, фоновое декодирование изображений и сетевую работу во время прокрутки.

## Выбор кузова

Фильтр «Кузов» реализован доступным custom picker с синхронизированным нативным значением формы. Справа от названия и в открытом списке показывается SVG-силуэт выбранного типа: sedan, universal, hatchback, liftback, SUV, minivan, minibus, coupe, cabriolet, pickup или van. Силуэты встроены в HTML и работают офлайн, без внешних картинок.

## VIN и полная история

В каждой карточке есть постоянно доступная и визуально выделенная кнопка **«Полный отчёт по VIN»**. Поле ручного ввода показывается **сразу после открытия окна**, до завершения каких-либо сетевых запросов: медленная площадка или скрытый номер больше не оставляют пользователя перед одним spinner. Параллельно MOTOR.BY загружает полную карточку, а для AV.BY пробует официальный маршрут Android-приложения `offer-types/cars/offers/:advertId/vin` через собственный endpoint `/api/av/vin/:advertId`. Если AV.BY отдаёт номер, проверка продолжается автоматически. Сейчас поставщик требует пользовательский JWT и применяет собственный лимит просмотров, поэтому сайт не обходит авторизацию, не запрашивает чужой логин/пароль и в таком случае оставляет готовое поле для ручного ввода 17-символьного VIN из техпаспорта, с кузова или со слов продавца.

Endpoint `/api/vin/:vin` всегда возвращает перечень доступных проверок и прямые ссылки на поставщиков, даже если вспомогательная техническая расшифровка NHTSA временно недоступна. При доступности NHTSA ответ также содержит бесплатные технические характеристики. Прямые ссылки ведут на:

- коммерческий полный отчёт AV.BY по конкретному VIN;
- проверку залогов, ограничений и истории размещений Kufar;
- официальную проверку розыска МВД РБ на e-pasluga (требует авторизации портала).

Панель перечисляет 12 категорий: ДТП в Беларуси и России, повреждения и расчёты ремонта, пробег за 10 лет, обслуживание и техосмотры, регистрации/владельцев, залоги/ограничения/розыск, таможню, историю продаж, такси/каршеринг, страхование и выплаты, аварийные аукционы и отзывные кампании.

Количество ДТП, зафиксированных ремонтов, владельцев и прочие фактические результаты не являются открытыми бесплатными данными. Они появляются только после формирования коммерческого отчёта поставщиком. Интерфейс явно помечает такие пункты как **«Результат в полном отчёте»** и ведёт на VIN-specific страницу AV.BY; нулевые значения и «чистая история» не фабрикуются.

## Google-аккаунт и синхронизация между устройствами

Актуальная сборка включает отдельную кнопку аккаунта в шапке и вход **только через Google** посредством Supabase Auth. После входа приватная облачная строка становится основной и синхронизирует между телефонами и компьютерами:

- избранные автомобили и их актуальные снимки;
- выбранные для сравнения автомобили;
- заметки, просмотры, изменения цены и наличия;
- сохранённые наборы фильтров;
- тему, плотность, сортировку, валюту и последнюю форму поиска.

Изменения объединяются в ограниченный JSON payload и автоматически записываются примерно через 1,8 секунды. При открытии на другом устройстве облачная копия заменяет локальную, как выбрано для этого релиза. Если строки аккаунта ещё нет, существующие локальные данные становятся первой облачной копией, чтобы первый вход ничего не удалил. После выхода изменения сначала сохраняются, затем личные данные очищаются из IndexedDB устройства; облачная копия остаётся.

Для изоляции пользователей таблица `motorby_user_state` использует PostgreSQL Row Level Security: `auth.uid()` должен совпадать с `user_id` при каждом `SELECT`, `INSERT`, `UPDATE` и `DELETE`. В браузер передаётся только publishable/anon key; `service_role`, пароль базы и Google Client Secret в приложение не попадают. Готовая схема находится в `supabase/schema.sql`, а настройка без терминала — в [`SUPABASE-GOOGLE-SETUP.md`](SUPABASE-GOOGLE-SETUP.md).

## Личная база, история и офлайн-режим

Без входа личная база на **IndexedDB** продолжает работать полностью в браузере посетителя. После Google-входа IndexedDB становится локальной офлайн-копией защищённого состояния Supabase. Заметная кнопка **«Избранное»** с сердцем и счётчиком в шапке открывает личную панель, где доступны:

- отдельный список всех избранных автомобилей с фото, ценой, статусом, удалением и ссылкой на оригинал;
- просмотр избранного полноценными внутренними карточками через кнопку **«Карточками»**;
- просмотренные объявления;
- личные заметки в раскрытом блоке **«Все данные»** каждой карточки;
- сохранённые наборы фильтров;
- постоянные настройки сортировки, плотности карточек, темы интерфейса и валюты диапазона цены;
- экспорт всех данных в переносимый JSON и обратный импорт;
- автоматическая миграция избранного из прежнего `localStorage`.

Для каждого реально полученного объявления сохраняется компактный снимок цены, состояния и основных характеристик. При следующем живом получении интерфейс добавляет событие снижения/роста цены или возврата объявления. Избранные, недавно просмотренные и снабжённые заметкой записи старше 12 часов осторожно перепроверяются через detail-канал (не более шести за фоновый цикл). **Только явный `404` / `not_available`** считается исчезновением; CORS, таймаут, `429`, `5xx` и общий сбой источника не помечают автомобиль как снятый с продажи. История ограничена последними 40 событиями на объявление.

PWA-комплект состоит из `manifest.webmanifest`, корневого `sw.js` и иконок `192/512 px`. После первого успешного открытия MOTOR.BY можно установить на домашний экран. Service Worker сохраняет application shell, обе hero-фотографии тем, локальные изображения интерфейса и ограниченный runtime-кэш фотографий. При отсутствии сети shell запускается, а последняя выдача восстанавливается из IndexedDB с явной пометкой **«Офлайн-режим»**; API-ответы поиска никогда не выдаются за свежие. На iPhone установка выполняется через **Поделиться → На экран Домой**.

## Умная загрузка фотографий

- при обычной прокрутке соседние кадры не загружаются в фоне; запрос начинается после явного свайпа, нажатия стрелки или открытия lightbox;
- после первого взаимодействия текущий, предыдущий и следующий кадры подготавливаются с учётом `Save-Data` и типа соединения;
- перед показом используется `HTMLImageElement.decode()`;
- decoded working set ограничен 12 изображениями на desktop и 8 на телефоне, Service Worker runtime-кэш — 72 ответами; старые элементы удаляются;
- AV.BY по-прежнему загружает `avcdn.av.by` напрямую из браузера, а остальные разрешённые CDN — через защищённый `/api/media`.

## Честность данных

- API отвечает `live: true` и `mock: false`.
- При ошибке источника тестовые или демонстрационные автомобили не подставляются.
- Сбой одного адаптера не останавливает остальные: frontend показывает его собственный статус.
- У дилерских каталогов принимаются только публичные записи с положительным складским остатком, фотографией, ценой и статусом `AVAILABLE` либо `BOOKED`.
- Забронированный автомобиль не маскируется под свободный: на карточке явно написано **«Забронирован»**.
- Проданные, архивные, отключённые, неидентифицируемые и лишённые обязательных данных записи отбрасываются.
- Цена и наличие всё равно должны подтверждаться на оригинальной странице — ссылка присутствует в каждой карточке.

## Как подключены дилеры и автохаусы

Используется публичный JSON stock-сервис Атлант-М без токена:

```text
POST https://stock-service.atlantm.by/api/cars/search
GET  https://stock-service.atlantm.by/api/cars/:id
```

Категории разделены исходным типом склада:

- `type: "new"` → источник `dealer`;
- `type: "amp"` → источник `autohouse`.

Для покрытия всей Беларуси frontend параллельно использует каталог компаний публичного Android API AV.BY:

- `seller_type[0]=2` + `condition[0]=5` → новые автомобили дилеров и автосалонов;
- `seller_type[0]=2` + `condition[0]=2` → автомобили с пробегом автохаусов и автосалонов.

Результаты двух провайдеров чередуются внутри категории и дедуплицируются с общей выдачей AV.BY по исходному ID. Региональный фильтр передаётся AV.BY, поэтому доступны компании Бреста, Витебска, Гомеля, Гродно, Могилёва, Минска, областей и поддерживаемых городов.

Поиск Атлант-М передаёт `offset`, `limit`, сортировку и сериализованный путь фильтров. Поддерживаются марка, модель, цена, год, пробег для авто с пробегом, кузов, топливо, коробка и привод. Detail endpoint предоставляет поколение (когда опубликовано), VIN, цвет, мощность, размеры, оснащение, гарантию, статус, дилера, адрес, телефон и полную галерею.

Особенности:

- склад Атлант-М в этой интеграции относится к Минску и ближайшему Минскому району, а национальное покрытие категорий обеспечивают business-объявления AV.BY;
- при выборе другого города/региона Атлант-М не подставляет минские автомобили, но интерфейс продолжает показывать подходящие компании выбранного региона из AV.BY;
- used stock не публикует поколение в списке, поэтому при выбранных поколениях `autohouse` проверяет detail-карточки и не расширяет поиск до всей модели;
- в detail автохауса поколение дополняется taxonomy Onlíner только тогда, когда год попадает ровно в один диапазон поколения; при пересечении диапазонов значение остаётся пустым;
- у новых машин выбранные поколения сверяются с detail-карточками;
- у новых автомобилей одометр не публикуется: `mileageTo` не должен ошибочно удалять весь новый склад.

## Как подключён AV.BY

AV.BY может ограничивать общий серверный egress Render защитой SafeLine. Чтобы выдача сайта не зависела от минутного лимита резервного reader, frontend получает поиск и detail-карточки напрямую из публичного Android API `https://android-api.av.by/`. API разрешает CORS, запрос выполняется браузером посетителя без ключей, а ответ нормализуется в ту же внутреннюю структуру MOTOR.BY.

Backend остаётся независимым резервным маршрутом для браузеров или сетей, где прямой CORS-запрос не прошёл:

1. прямой серверный запрос к публичному Android API;
2. при блокировке серверного адреса — публичный Jina Reader `https://r.jina.ai/` как последний read-only транспорт;
3. устаревший кэш при кратковременном сбое источника.

Таким образом обычный поиск на сайте не расходует минутную квоту Reader. Изображения `avcdn.av.by` также загружаются браузером напрямую с `referrerpolicy="no-referrer"`.

Для снижения нагрузки предусмотрены:

- TTL-кэш поиска, detail-карточек и taxonomy;
- локальный 30-минутный резерв последней точной AV.BY-выдачи с явной пометкой **«из локального кэша»**;
- объединение одинаковых параллельных запросов (`inflight deduplication`);
- локальный бюджет до 18 обращений к Reader за 60 секунд;
- пауза перед повторной прямой попыткой после блокировки;
- устаревший кэш при кратковременном сбое источника.

AV.BY использует диапазоны `[min]` / `[max]`; неверный для него формат `[from]` / `[to]` не применяется.

> Jina Reader — внешний публичный сервис. Перед коммерческой эксплуатацией проверьте актуальные условия использования всех источников и транспорта.

## Быстрый деплой на Render

Полная пошаговая инструкция от распаковки архива до проверки сайта: **[`DEPLOY-GITHUB-RENDER.md`](DEPLOY-GITHUB-RENDER.md)**.

2. В Render выберите **New → Blueprint**.

4. Render прочитает `render.yaml` и создаст Node Web Service.
5. После сборки откройте выданный адрес `https://….onrender.com`.

- Build command: `npm install --omit=dev`

Render Free засыпает после 15 минут без входящего трафика. Готовая конфигурация в `cloudflare-worker/` создаёт Cloudflare Cron Trigger `*/10 * * * *`, который вызывает только лёгкий `/api/health`. Укажите свой Render URL в `cloudflare-worker/wrangler.toml`, затем выполните `npx wrangler login` и `npx wrangler deploy`. Это бесплатный практичный вариант без гарантии SLA; платные экземпляры Render не засыпают.

## API

### `GET /api/health`

Проверяет Web Service без лишних внешних запросов. Возвращает:

- конфигурацию каталогов Атлант-М;

- последнее состояние транспорта AV.BY;
- статистику кэша.

### `GET /api/account-config`

Возвращает браузеру публичную конфигурацию Supabase только тогда, когда в Render корректно заданы `SUPABASE_URL` и `SUPABASE_ANON_KEY`. `enabled: false` оставляет сайт в локальном режиме. Service-role key и Google Client Secret этот endpoint не принимает и не выдаёт.

### `GET /api/exchange`

Возвращает курс `USD → BYN` из официального публичного API НБРБ без ключа:

```json
{
  "live": true,
  "mock": false,
  "base": "USD",
  "quote": "BYN",
  "rate": 3.0286,
  "effectiveDate": "2026-09-16T00:00:00",
  "source": "НБРБ"
}
```

`rate` уже нормализован на один доллар с учётом `Cur_Scale`. При резервном ответе `live` равен `false`, а поле `notice` объясняет причину.

### `GET /api/catalog/brands`

Объединённый справочник марок Onlíner, дилеров и автохауса. Onlíner остаётся основной taxonomy, а отсутствующие складские марки получают стабильные внутренние отрицательные ID. При кратковременном сбое основной площадки ответ явно помечает резервный список.

### `GET /api/catalog/models?brand=5`

Модели марки; `5` — BMW в каталоге Onlíner. Ответ дополняется отсутствующими моделями stock-каталогов. Для добавленных моделей используются стабильные отрицательные ID; остальные адаптеры сопоставляют их по названию и не отправляют неверный ID в Onlíner.

### `GET /api/catalog/generations?brand=5&model=1163`

Поколения модели, годы и изображения; `1163` — BMW X5.

### `GET /api/search`

Единый поиск. Если `source` не указан, используются все пять источников.

| Параметр | Пример | Назначение |
|---|---|---|
| `source` | `onliner`, `kufar`, `av`, `dealer`, `autohouse` | Можно передать несколько раз |
| `brand`, `brandName` | `5`, `BMW` | ID Onlíner и название для межплощадочного сопоставления |
| `model`, `modelName` | `1163`, `X5` | ID Onlíner и название модели |
| `generation`, `generationName` | `6052`, `F15` | Повторяемая пара ID Onlíner и названия поколения; для нескольких поколений передайте параметры несколько раз |
| `priceFrom`, `priceTo` | `30000`, `100000` | Цена, BYN |
| `yearFrom`, `yearTo` | `2018`, `2026` | Годы выпуска |
| `mileageTo` | `150000` | Максимальный пробег, км |
| `mode` | `all`, `owned`, `new`, `electric` | Состояние / электротяга |
| `body` | `suv`, `sedan`, `universal` | Кузов |
| `fuel` | `gasoline`, `diesel`, `hybrid`, `electric`, `gas` | Топливо |
| `transmission` | `automatic`, `mechanical` | Коробка |
| `drivetrain` | `front`, `rear`, `all` | Привод |
| `city` | `minsk`, `brest`, `minsk_region` | Город или область |
| `sort` | `fresh`, `priceAsc`, `priceDesc`, `yearAsc`, `yearDesc`, `mileageAsc`, `mileageDesc` | Порядок источника и итоговой выдачи |
| `page` | `1`…`5` | Страница источника; Kufar использует cursor |
| `limit` | `4`…`16` | Лимит на каждый источник |

Пример общей выдачи:

```text
/api/search?source=onliner&source=kufar&source=av&source=dealer&source=autohouse&brand=5&brandName=BMW&model=1163&modelName=X5&priceTo=100000&city=minsk
```

Ответ содержит отдельный `sourceStatus` для каждого выбранного источника. AV.BY дополнительно сообщает использованный `transport`. Несопоставленная taxonomy не заменяется более широкими неподходящими результатами.

В браузерном интерфейсе категории `dealer` и `autohouse` дополнительно объединяются с национальным каталогом компаний AV.BY. Сам серверный `GET /api/search?source=dealer|autohouse` сохраняет независимый stock-ответ Атлант-М, чтобы при блокировке внешнего CORS-маршрута хотя бы один проверенный провайдер продолжал работать.

### `GET /api/listing/:source/:id`

Полная нормализованная карточка:

```text
/api/listing/onliner/5066833
/api/listing/kufar/1084016485
/api/listing/av/139059662
/api/listing/dealer/12348508
/api/listing/autohouse/AA00017231
```

Возвращает галерею, продавца/дилера, источник и каталог, описание, характеристики, оснащение и доступные условия. Телефон присутствует только у источников, которые публикуют его структурированно; сейчас это дилерский stock-каталог Атлант-М.

Detail Onlíner, Kufar, дилеров и автохаусов подгружается для видимых карточек. Расширенный detail AV.BY запрашивается при раскрытии комментария или блока «Все данные», чтобы беречь лимит резервного транспорта.

### `GET /api/media?url=...`

Same-origin image proxy с HTTPS allowlist:

- `content.onliner.by`, `imgproxy.onliner.by`;
- `rms.kufar.by` и `rmsN.kufar.by`;
- `avcdn.av.by`;
- `io.activecloud.com`, `dealers-service.atlantm.by`.

Каждый redirect проверяется заново. Не-изображения, неизвестные домены, пустые и слишком большие ответы блокируются, поэтому endpoint нельзя использовать как произвольный SSRF-прокси.

## Единая структура объявления

Ключевые поля:

- `source`, `sourceLabel`, `sourceCatalog`, `provider`, `sourceId`, `sourceUrl`;
- `title`, `brand`, `model`, `generation`, `modification`;
- `generationImage`, `generationYears`;
- `priceByn`, `priceUsd`, исходная цена до скидки;
- `year`, `mileage`, `transmission`;
- `engineVolume`, `enginePower`, `fuel`;
- `body`, `drivetrain`, `state`, `color`, `vin`;
- `location`, `seller` (включая телефон, если опубликован);
- `images`, `description`, `equipment`;
- `dealTerms`, `createdAt`, `updatedAt`, `collectedAt`;
- `descriptionLoaded`, `detailLoaded`, `detailAvailable`.

## Надёжность и настройки

По умолчанию:

- поиск кэшируется на 3 минуты;
- detail — на 10 минут;
- справочники — на 6–12 часов;
- одинаковые запросы объединяются;
- внешние запросы имеют таймауты;
- search/detail/media защищены in-memory rate limit;
- изображения проходят строгий allowlist;
- формат и ошибка каждого источника изолированы;
- личные данные ограничены браузером и доступны для JSON-экспорта;
- application shell и изображения имеют раздельные версионированные PWA-кэши.

Переменные окружения:

```text
SEARCH_CACHE_TTL=180
DETAIL_CACHE_TTL=600
MARKET_CACHE_TTL=1200
CATALOG_CACHE_TTL=21600
AV_TAXONOMY_CACHE_TTL=43200
AV_SOURCE_TIMEOUT_MS=14000
SOURCE_USER_AGENT=MotorBY-Aggregator/1.10.0 (...)
```

`render.yaml` уже содержит базовые значения.

## Ограничения

1. Публичные внутренние форматы площадок могут измениться. Соответствующий адаптер вернёт `format_changed`/`error`, остальные продолжат работать.
2. Прямой egress AV.BY зависит от сети Render; поэтому транспорт определяется во время выполнения.
3. Бесплатный Render-инстанс может засыпать; первый запрос после сна будет медленнее.
4. Категории дилеров и автохаусов объединяют Атлант-М с business-каталогом AV.BY; состав компаний и число объявлений меняются в реальном времени на стороне источников.
5. У used stock Атлант-М нет структурированного поколения; дополнение по году выполняется только при одном возможном диапазоне, а неоднозначные поколения не угадываются.
6. Цены, бронь и наличие меняются. Истиной остаётся оригинальная карточка; локальная история обновляется только при успешном получении или явном ответе об отсутствии.
7. IndexedDB, заметки и избранное принадлежат конкретному профилю браузера. Для переноса на другое устройство используйте экспорт/импорт в панели **«Избранное»**.
8. Первый офлайн-запуск возможен только после хотя бы одного успешного онлайн-открытия, когда Service Worker сохранил shell.
9. Перед публичным или коммерческим запуском проверьте условия использования и `robots.txt` источников.

## Диагностика

1. Откройте `/api/health`.
2. Проверьте источники отдельно:

```text
/api/search?source=onliner&limit=4
/api/search?source=kufar&limit=4
/api/search?source=av&limit=4
/api/search?source=dealer&limit=4
/api/search?source=autohouse&limit=4
```

3. Для AV.BY в браузерном интерфейсе ожидается `sourceStatus[0].transport: "browser-direct"`; блок `av` в health показывает конфигурацию серверного резерва.
4. Если объявления AV.BY есть, но изображений нет, откройте один запрос `/api/media?url=https%3A%2F%2Favcdn.av.by%2F...`. Код `http_423` означает блокировку shared egress Render со стороны CDN, а не отсутствие фотографии. Начиная с версии `1.2.2`, строго разрешённый `avcdn.av.by` загружается браузером напрямую с `referrerpolicy="no-referrer"`; `/api/media` для старых ссылок безопасно перенаправляет туда же.
5. Для дилеров и автохаусов проверьте `businessCatalogs` в health, поля `provider`, `sourceCatalog`, `sourceUrl` и наличие карточек компаний из регионов за пределами Минска.
6. Проверьте `/manifest.webmanifest` и `/sw.js`: оба адреса должны возвращать `200`, а `/sw.js` — заголовок `Service-Worker-Allowed: /`.
7. Для проверки офлайн-режима сначала один раз откройте сайт онлайн, затем в DevTools → Application дождитесь активного Service Worker и включите Offline. Последняя выдача должна получить явную локальную пометку.
8. Посмотрите Render Logs при статусе `error`.

Статусы `blocked`, `timeout`, `format_changed` и `error` отражают реальную проблему источника. Сайт намеренно не скрывает её под фиктивными карточками.

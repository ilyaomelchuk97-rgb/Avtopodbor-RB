# MOTOR.BY — автомобильный агрегатор по Беларуси

Готовый к размещению **Render Web Service** без API-ключей. Backend получает реальные объявления и складские карточки из публичных каналов источников, приводит их к единой структуре, а frontend показывает автомобили непосредственно на сайте в адаптивном премиальном тёмном интерфейсе.

## Подключённые источники

1. **Onlíner Автобарахолка** — поиск, фильтры, полная карточка, комментарий продавца, оснащение, галерея и изображения поколений.
2. **Kufar Авто** — SSR-каталог, фильтры, cursor-пагинация, полная карточка, описание продавца и настоящие фотографии.
3. **AV.BY** — публичный мобильный каталог: поиск, фильтры, города/области, полная карточка, оснащение и фотографии `avcdn.av.by`.
4. **Дилеры** — склад новых автомобилей официальных дилеров Атлант-М: отдельные автомобили, реальные цены и скидки, фотографии, комплектации, статусы наличия, адреса, телефоны и подробное оснащение.
5. **Автохаусы** — каталог «Атлант-М Автомобили с пробегом»: отдельные автомобили, цены, пробег, фотографии, характеристики, адреса, телефоны и полный комментарий автохауса.

«Дилеры» и «Автохаусы» являются отдельными переключателями и одновременно участвуют в общей выдаче. Конкретный поставщик и каталог явно указаны в каждой карточке:

- `Дилеры · Атлант-М` / `Новые автомобили официальных дилеров`;
- `Автохаус · Атлант-М` / `Атлант-М Автомобили с пробегом`.

Справочник марок и моделей объединяет taxonomy Onlíner со складскими каталогами дилеров и автохауса, поэтому новые дилерские марки/модели не исчезают из фильтра. Поколения Onlíner содержат годы и каталожные изображения; в выпадающем выборе модели счётчик поколений не показывается. Для модели, у которой источник не публикует поколения, интерфейс не рисует фиктивные варианты.

## Адаптивность

Интерфейс отдельно оптимизирован под **iPhone 13 mini (375 × 812 CSS px)** и другие компактные экраны:

- учтены `safe-area-inset-*`, вырез экрана и нижний Home Indicator;
- поля имеют шрифт 16 px, поэтому Safari не увеличивает страницу при фокусе;
- интерактивные элементы имеют удобные touch-зоны около 44 px;
- фильтры, статусы, карточки и кнопки не выходят за ширину 375 px;
- галерея использует динамическую высоту viewport и безопасные отступы;
- предусмотрена отдельная компоновка для альбомной ориентации.

## Честность данных

- API отвечает `live: true` и `mock: false`.
- При ошибке источника тестовые или демонстрационные автомобили не подставляются.
- Сбой одного адаптера не останавливает остальные: frontend показывает его собственный статус.
- У дилерских каталогов принимаются только публичные записи с положительным складским остатком, фотографией, ценой и статусом `AVAILABLE` либо `BOOKED`.
- Забронированный автомобиль не маскируется под свободный: на карточке явно написано **«Забронирован»**.
- Проданные, архивные, отключённые, неидентифицируемые и лишённые обязательных данных записи отбрасываются.
- Цена и наличие всё равно должны подтверждаться на оригинальной странице — ссылка присутствует в каждой карточке.

## Как подключены дилеры и автохаусы

Используется публичный JSON stock-сервис Атлант-М без токена:

```text
POST https://stock-service.atlantm.by/api/cars/search
GET  https://stock-service.atlantm.by/api/cars/:id
```

Категории разделены исходным типом склада:

- `type: "new"` → источник `dealer`;
- `type: "amp"` → источник `autohouse`.

Поиск передаёт `offset`, `limit`, сортировку и сериализованный путь фильтров. Поддерживаются марка, модель, цена, год, пробег для авто с пробегом, кузов, топливо, коробка и привод. Detail endpoint предоставляет поколение (когда опубликовано), VIN, цвет, мощность, размеры, оснащение, гарантию, статус, дилера, адрес, телефон и полную галерею.

Особенности:

- склад Атлант-М в этой интеграции относится к Минску и ближайшему Минскому району;
- при выборе другого города/региона адаптер возвращает честный пустой статус и не показывает минские автомобили;
- used stock не публикует поколение структурированно, поэтому при выбранном поколении `autohouse` не расширяет поиск до всей модели;
- в detail автохауса поколение дополняется taxonomy Onlíner только тогда, когда год попадает ровно в один диапазон поколения; при пересечении диапазонов значение остаётся пустым;
- у новых машин выбранное поколение сверяется с detail-карточкой;
- у новых автомобилей одометр не публикуется: `mileageTo` не должен ошибочно удалять весь новый склад.

## Как подключён AV.BY

AV.BY может ограничивать серверный egress защитой SafeLine. Адаптер использует два транспорта:

1. прямой запрос к публичному Android API `https://android-api.av.by/`;
2. при блокировке — публичный Jina Reader `https://r.jina.ai/` как резервный read-only транспорт.

Ответ Reader содержит исходный JSON AV.BY в `data.content`; backend разбирает его и нормализует объявления. CAPTCHA не обходится, браузерная автоматизация не используется.

Для снижения нагрузки предусмотрены:

- TTL-кэш поиска, detail-карточек и taxonomy;
- объединение одинаковых параллельных запросов (`inflight deduplication`);
- локальный бюджет до 18 обращений к Reader за 60 секунд;
- пауза перед повторной прямой попыткой после блокировки;
- устаревший кэш при кратковременном сбое источника.

AV.BY использует диапазоны `[min]` / `[max]`; неверный для него формат `[from]` / `[to]` не применяется.

> Jina Reader — внешний публичный сервис. Перед коммерческой эксплуатацией проверьте актуальные условия использования всех источников и транспорта.

## Быстрый деплой на Render

Полная пошаговая инструкция от распаковки архива до проверки сайта: **[`DEPLOY-GITHUB-RENDER.md`](DEPLOY-GITHUB-RENDER.md)**.

### Blueprint

1. Загрузите файлы проекта в GitHub/GitLab.
2. В Render выберите **New → Blueprint**.
3. Подключите репозиторий.
4. Render прочитает `render.yaml` и создаст Node Web Service.
5. После сборки откройте выданный адрес `https://….onrender.com`.

Нужен именно **Web Service**, а не Static Site: внешние каталоги запрашивает backend.

### Ручная настройка

- Runtime: `Node`
- Build command: `npm install --omit=dev`
- Start command: `npm start`
- Health check: `/api/health`
- Node.js: 20 или новее

Секреты и API-ключи не требуются.

## Локальный запуск

```bash
npm install
npm start
```

Откройте <http://localhost:8080>.

Другой порт:

```bash
PORT=3000 npm start
```

Проверка backend:

```bash
npm run check
```

## API

### `GET /api/health`

Проверяет Web Service без лишних внешних запросов. Возвращает:

- пять включённых адаптеров;
- конфигурацию каталогов Атлант-М;
- последнее состояние транспорта AV.BY;
- статистику кэша.

### `GET /api/catalog/brands`

Объединённый справочник марок Onlíner, дилеров и автохауса. Onlíner остаётся основной taxonomy, а отсутствующие складские марки получают стабильные внутренние отрицательные ID. При кратковременном сбое основной площадки ответ явно помечает резервный список.

### `GET /api/catalog/models?brand=5`

Модели марки; `5` — BMW в каталоге Onlíner. Ответ дополняется отсутствующими моделями stock-каталогов. Для добавленных моделей используются стабильные отрицательные ID; остальные адаптеры сопоставляют их по названию и не отправляют неверный ID в Onlíner.

### `GET /api/catalog/generations?brand=5&model=1163`

Поколения модели, годы и изображения; `1163` — BMW X5.

### `GET /api/search`

Единый поиск. Если `source` не указан, используются все пять источников.

| Параметр | Пример | Назначение |
|---|---|---|
| `source` | `onliner`, `kufar`, `av`, `dealer`, `autohouse` | Можно передать несколько раз |
| `brand`, `brandName` | `5`, `BMW` | ID Onlíner и название для межплощадочного сопоставления |
| `model`, `modelName` | `1163`, `X5` | ID Onlíner и название модели |
| `generation`, `generationName` | `6052`, `F15` | ID Onlíner и название поколения |
| `priceFrom`, `priceTo` | `30000`, `100000` | Цена, BYN |
| `yearFrom`, `yearTo` | `2018`, `2026` | Годы выпуска |
| `mileageTo` | `150000` | Максимальный пробег, км |
| `mode` | `all`, `owned`, `new`, `electric` | Состояние / электротяга |
| `body` | `suv`, `sedan`, `universal` | Кузов |
| `fuel` | `gasoline`, `diesel`, `hybrid`, `electric`, `gas` | Топливо |
| `transmission` | `automatic`, `mechanical` | Коробка |
| `drivetrain` | `front`, `rear`, `all` | Привод |
| `city` | `minsk`, `brest`, `minsk_region` | Город или область |
| `page` | `1`…`5` | Страница; Kufar использует cursor |
| `limit` | `4`…`16` | Лимит на каждый источник |

Пример общей выдачи:

```text
/api/search?source=onliner&source=kufar&source=av&source=dealer&source=autohouse&brand=5&brandName=BMW&model=1163&modelName=X5&priceTo=100000&city=minsk
```

Ответ содержит отдельный `sourceStatus` для каждого выбранного источника. AV.BY дополнительно сообщает использованный `transport`. Несопоставленная taxonomy не заменяется более широкими неподходящими результатами.

### `GET /api/listing/:source/:id`

Полная нормализованная карточка:

```text
/api/listing/onliner/5066833
/api/listing/kufar/1084016485
/api/listing/av/139059662
/api/listing/dealer/12348508
/api/listing/autohouse/AA00017231
```

Возвращает галерею, продавца/дилера, источник и каталог, описание, характеристики, оснащение и доступные условия. Телефон присутствует только у источников, которые публикуют его структурированно; сейчас это дилерский stock-каталог Атлант-М.

Detail Onlíner, Kufar, дилеров и автохаусов подгружается для видимых карточек. Расширенный detail AV.BY запрашивается при раскрытии комментария или блока «Все данные», чтобы беречь лимит резервного транспорта.

### `GET /api/media?url=...`

Same-origin image proxy с HTTPS allowlist:

- `content.onliner.by`, `imgproxy.onliner.by`;
- `rms.kufar.by` и `rmsN.kufar.by`;
- `avcdn.av.by`;
- `io.activecloud.com`, `dealers-service.atlantm.by`.

Каждый redirect проверяется заново. Не-изображения, неизвестные домены, пустые и слишком большие ответы блокируются, поэтому endpoint нельзя использовать как произвольный SSRF-прокси.

## Единая структура объявления

Ключевые поля:

- `source`, `sourceLabel`, `sourceCatalog`, `provider`, `sourceId`, `sourceUrl`;
- `title`, `brand`, `model`, `generation`, `modification`;
- `generationImage`, `generationYears`;
- `priceByn`, `priceUsd`, исходная цена до скидки;
- `year`, `mileage`, `transmission`;
- `engineVolume`, `enginePower`, `fuel`;
- `body`, `drivetrain`, `state`, `color`, `vin`;
- `location`, `seller` (включая телефон, если опубликован);
- `images`, `description`, `equipment`;
- `dealTerms`, `createdAt`, `updatedAt`, `collectedAt`;
- `descriptionLoaded`, `detailLoaded`, `detailAvailable`.

## Надёжность и настройки

По умолчанию:

- поиск кэшируется на 3 минуты;
- detail — на 10 минут;
- справочники — на 6–12 часов;
- одинаковые запросы объединяются;
- внешние запросы имеют таймауты;
- search/detail/media защищены in-memory rate limit;
- изображения проходят строгий allowlist;
- формат и ошибка каждого источника изолированы.

Переменные окружения:

```text
SEARCH_CACHE_TTL=180
DETAIL_CACHE_TTL=600
CATALOG_CACHE_TTL=21600
AV_TAXONOMY_CACHE_TTL=43200
AV_SOURCE_TIMEOUT_MS=14000
SOURCE_USER_AGENT=MotorBY-Aggregator/1.2.1 (...)
```

`render.yaml` уже содержит базовые значения.

## Ограничения

1. Публичные внутренние форматы площадок могут измениться. Соответствующий адаптер вернёт `format_changed`/`error`, остальные продолжат работать.
2. Прямой egress AV.BY зависит от сети Render; поэтому транспорт определяется во время выполнения.
3. Бесплатный Render-инстанс может засыпать; первый запрос после сна будет медленнее.
4. Текущий дилерский/автохаусный провайдер — сеть Атлант-М. Архитектура допускает добавление других провайдеров под теми же категориями.
5. У used stock Атлант-М нет структурированного поколения; дополнение по году выполняется только при одном возможном диапазоне, а неоднозначные поколения не угадываются.
6. Цены, бронь и наличие меняются. Истиной остаётся оригинальная карточка.
7. Перед публичным или коммерческим запуском проверьте условия использования и `robots.txt` источников.

## Диагностика

1. Откройте `/api/health`.
2. Проверьте источники отдельно:

```text
/api/search?source=onliner&limit=4
/api/search?source=kufar&limit=4
/api/search?source=av&limit=4
/api/search?source=dealer&limit=4
/api/search?source=autohouse&limit=4
```

3. Для AV.BY проверьте `sourceStatus[0].transport` и блок `av` в health.
4. Для дилеров проверьте поля `provider`, `catalog`, `sourceUrl` и detail endpoint.
5. Посмотрите Render Logs при статусе `error`.

Статусы `blocked`, `timeout`, `format_changed` и `error` отражают реальную проблему источника. Сайт намеренно не скрывает её под фиктивными карточками.

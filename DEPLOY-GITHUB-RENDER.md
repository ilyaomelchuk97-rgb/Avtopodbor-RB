# Как загрузить MOTOR.BY на GitHub и развернуть на Render

Ниже — пошаговая инструкция для человека без опыта деплоя. Проект уже содержит `render.yaml`, поэтому рекомендуемый способ — **Render Blueprint**.

Инструкция относится к актуальной сборке **`1.10.0`**.

Официальные справки:

- GitHub: <https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github>
- Render Blueprints: <https://render.com/docs/infrastructure-as-code>
- Render Health Checks: <https://render.com/docs/health-checks>

---

## 1. Что понадобится

1. Аккаунт на <https://github.com>.
2. Аккаунт на <https://render.com>.
3. Архив `motor-by-site.zip` из этой сборки.
4. Аккаунт на <https://supabase.com> и Google-аккаунт для входа пользователей.
5. Для варианта с командами — установленный Git: <https://git-scm.com/downloads>.

API-ключи для автомобильных источников не нужны. Для аккаунтов потребуются публичные Supabase Project URL/publishable key и Google OAuth credential; Google Client Secret вводится только в Supabase.

## 2. Подготовьте файлы

1. Скачайте `motor-by-site.zip`.
2. Полностью распакуйте архив в отдельную папку, например `motor-by-site`.
3. Откройте эту папку и проверьте структуру:

```text
motor-by-site/
├── server.js
├── index.html
├── manifest.webmanifest
├── sw.js
├── package.json
├── package-lock.json
├── render.yaml
├── README.md
├── DEPLOY-GITHUB-RENDER.md
├── SUPABASE-GOOGLE-SETUP.md
├── supabase/schema.sql
├── cloudflare-worker/
├── .gitignore
└── assets/
    ├── hero-car.jpg / hero-car-light.jpg
    ├── category-city.jpg
    ├── supabase-js-2.116.0.js / SUPABASE-LICENSE.txt
    ├── favicon.svg / favicon.ico / favicon-32.png
    ├── apple-touch-icon.png
    └── icon-192.png / icon-512.png / icon-maskable-512.png
```

### Важно

На GitHub нужно загрузить **содержимое распакованной папки**, а не один ZIP-файл. `package.json` и `render.yaml` должны находиться в корне репозитория, а не внутри дополнительной вложенной папки.

Правильно:

```text
github.com/USER/motor-by/server.js
github.com/USER/motor-by/render.yaml
```

Неправильно:

```text
github.com/USER/motor-by/motor-by-site/server.js
```

## 3. Создайте репозиторий GitHub

1. Войдите на <https://github.com>.
2. Нажмите **+** в правом верхнем углу.
3. Выберите **New repository**.
4. В поле **Repository name** укажите, например:

```text
motor-by
```

5. Выберите видимость:
   - **Public** — проще подключить к Render;
   - **Private** — тоже работает, но Render нужно предоставить доступ к репозиторию.
6. Если будете использовать команды Git, не включайте автоматическое создание README, `.gitignore` или License: эти файлы уже есть в проекте.
7. Нажмите **Create repository**.

---

## 4. Загрузите проект на GitHub

Есть два способа. Выберите только один.

### Способ A — через сайт GitHub

1. Откройте созданный пустой репозиторий.
2. Нажмите ссылку **uploading an existing file** или **Add file → Upload files**.
3. Перетащите в область загрузки всё содержимое распакованной папки:
   - основные файлы;
   - папку `assets` вместе с изображениями, favicon и тремя PWA-иконками;
   - корневые файлы `manifest.webmanifest` и `sw.js`.
4. Убедитесь, что `server.js`, `index.html`, `package.json` и `render.yaml` находятся на верхнем уровне.
5. В поле сообщения коммита напишите:

```text
Initial MOTOR.BY deploy
```

6. Выберите **Commit directly to the main branch**.
7. Нажмите **Commit changes**.

После загрузки откройте папку `assets` на GitHub и убедитесь, что внутри есть два JPG-файла, favicon/Apple icon и PWA-иконки `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`.

### Способ B — через Git в терминале

Откройте терминал в распакованной папке проекта и выполните:

```bash
git init -b main
git add .
git commit -m "Initial MOTOR.BY deploy"
git remote add origin https://github.com/ВАШ_ЛОГИН/motor-by.git
git push -u origin main
```

Замените `ВАШ_ЛОГИН` своим именем пользователя GitHub.

Если Git перед первым коммитом просит настроить автора, используйте собственные данные через настройки GitHub Desktop либо локальную конфигурацию Git. Проект не содержит и не требует чужих контактных данных или криптографических ключей.

GitHub не принимает пароль аккаунта как пароль для Git. При необходимости используйте вход через браузер, GitHub Desktop, SSH или Personal Access Token.

После отправки обновите страницу репозитория и проверьте, что файлы появились в ветке `main`.

## 5. Подключите GitHub к Render

1. Войдите на <https://dashboard.render.com>.
2. Нажмите **New → Blueprint**.
3. Если GitHub ещё не подключён, нажмите подключение GitHub и разрешите Render доступ:
   - ко всем репозиториям; или
   - только к репозиторию `motor-by`.
4. Найдите репозиторий `motor-by` и нажмите **Connect**.
5. В форме Blueprint укажите:
   - **Blueprint Name**: например `motor-by`;
   - **Branch**: `main`;
   - **Blueprint Path**: `render.yaml` или оставьте значение по умолчанию.
6. Render покажет создаваемый Web Service. Проверьте основные значения:

```text
Service type: Web Service
Runtime: Node
Build command: npm install --omit=dev
Start command: npm start
Health check: /api/health
```

7. Нажмите **Deploy Blueprint**.
8. Дождитесь завершения сборки и запуска.

В логах запуска должна появиться строка примерно такого вида:

```text
Motor BY listening on 0.0.0.0:10000
```

Render сам передаёт порт через переменную `PORT`; вручную указывать порт не нужно.

После успешного деплоя Render покажет адрес примерно такого вида:

```text
https://motor-by.onrender.com
```

Если имя уже занято, Render добавит суффикс или предложит другое имя.

### Подключите Google-аккаунты

До итоговой проверки выполните отдельную инструкцию **[`SUPABASE-GOOGLE-SETUP.md`](SUPABASE-GOOGLE-SETUP.md)**. Всё делается через панели Supabase, Google Cloud и Render без терминала:

1. выполнить `supabase/schema.sql` в Supabase SQL Editor;
2. включить Google provider;
3. разрешить точный Render URL для OAuth-возврата;
4. добавить в Render `SUPABASE_URL` и `SUPABASE_ANON_KEY`;
5. выполнить новый deploy.

Не помещайте Google Client Secret или Supabase `service_role` key в Render, GitHub либо HTML.

## 6. Проверьте сайт после деплоя

Откройте:

```text
https://ВАШ-СЕРВИС.onrender.com
```

Затем проверьте health endpoint:

```text
https://ВАШ-СЕРВИС.onrender.com/api/health
```

Ожидаемый ответ содержит:

```json
{
  "status": "ok",
  "service": "motor-by",
  "adapters": {
    "onliner": "enabled",
    "kufar": "enabled",
    "av": "enabled",
    "dealer": "enabled",
    "autohouse": "enabled"
  },
  "onliner": {
    "transport": null,
    "searchDelivery": "server-direct-with-relay-fallback",
    "detailDelivery": "server-direct-with-relay-fallback"
  }
}
```

До первого запроса `onliner.transport` может быть `null`. Откройте `https://ВАШ-СЕРВИС.onrender.com/api/search?source=onliner&page=1`, убедитесь, что `live` равно `true`, `mock` равно `false`, `items` не пуст, а `sourceStatus[0].state` равно `ok`. После этого health покажет `onliner.transport: "direct"` либо `"reader"`; значение `reader` нормально для исходящих IP Render, которым Onlíner не отвечает напрямую.

Для сборки `1.10.0` также проверьте поля `version: "1.10.0"` и `businessCatalogs`: обе категории должны иметь `coverage: "Belarus"` и `delivery: "server-plus-browser-direct"`.

После этого на главной странице:

1. выберите один или несколько источников;
2. нажмите **«Показать объявления»**;
3. проверьте несколько фотографий AV.BY и Onlíner, перелистывание, а также каталожное фото поколения; внешние CDN должны загружаться напрямую, без `/api/media`;
4. раскройте **«Все данные»**;
5. откройте ссылку **«Оригинал»**;
6. переключите режим **«Подробно / Компактно»**;
7. нажмите сердце на двух автомобилях, откройте **«Избранное»** в шапке, проверьте отдельный список и кнопку **«Карточками»**, затем добавьте заметку и сохраните фильтр;
8. найдите несколько автомобилей одной модели и проверьте справа от цены шкалу с минимумом, максимумом, белым маркером и оценкой **«Низкая / Средняя по рынку / Высокая цена»**; для редкой модели дождитесь догрузки `/api/market` и убедитесь, что fallback показывает центрированный маркер и **«Средняя цена»**, а не «Мало данных»;
9. переключите тему в шапке: hero-фото, синий accent и фон должны измениться, а выбор — сохраниться после перезагрузки; в обеих темах проверьте статичные полупрозрачные поверхности, ровную верхнюю линию цвета источника и отсутствие волнистого бокового преломления, параллакса и декоративного движения;
10. откройте выбор **«Кузов»** и проверьте силуэт справа для нескольких типов;
11. в диапазоне цены введите `30000–60000 BYN`, переключите на USD и обратно; значения должны пересчитаться, а подпись — показать курс НБРБ; долларовый эквивалент карточки должен совпадать с `цена BYN / курс` и иметь пометку «НБРБ»; выполните поиск в USD и убедитесь, что `/api/search` получил нормализованные BYN-пределы;
12. нажмите **«Поделиться»**: на телефоне должно открыться системное меню, а при его отсутствии — скопироваться deep link с фильтрами, валютой, сортировкой и страницей;
13. добавьте четыре карточки в сравнение: первые три должны попасть в нижнюю панель, четвёртая — показать ограничение; откройте адаптивную таблицу, удалите позицию и перезагрузите страницу для проверки локального сохранения;
14. нажмите **«Войти»**, авторизуйтесь через Google, сохраните автомобиль, сравнение, заметку и фильтр; через 2–3 секунды проверьте статус облачной копии, затем войдите тем же аккаунтом в другом браузере — облачные данные должны заменить локальные;
15. справа от **«Свежие объявления: n»** нажмите квадратную кнопку с карточками; свайпните первую карточку влево, вторую вправо и убедитесь, что только вторая появилась в Избранном; повторите действия нижними кнопками и клавишами `←` / `→`;
16. нажмите **«3D по фото»** в двух разных карточках: только после нажатия должны загрузиться фотографии выбранного объявления; проверьте разные персональные ракурсы, вращение мышкой/пальцем, масштабирование колесом/щипком, сброс камеры и ссылку на оригинал; на viewport `375 × 812` все блоки должны быть видны, а соседние панели — соприкасаться без щелей;
17. в карточке нажмите **«Полный отчёт по VIN»**: при опубликованном VIN должна появиться техническая расшифровка, 12 категорий и реальные внешние проверки; при отсутствующем — явное сообщение и поле ручного ввода VIN без выдуманных результатов;
18. проверьте `https://ВАШ-СЕРВИС.onrender.com/manifest.webmanifest`, `/sw.js`, `/assets/hero-car.jpg`, `/api/account-config`, `/api/exchange`, `/api/market?brandName=BMW&modelName=X5` и `/api/health`.

Первый запуск бесплатного Web Service после периода бездействия может занимать больше времени, чем последующие запросы.

## 7. Альтернативный способ: создать Web Service вручную

Если Blueprint не используется:

1. В Render нажмите **New → Web Service**.
2. Подключите репозиторий `motor-by`.
3. Выберите ветку `main`.
4. Заполните:

| Поле Render | Значение |
|---|---|
| Language / Runtime | Node |
| Region | Frankfurt или ближайший доступный |
| Branch | `main` |
| Root Directory | оставить пустым |
| Build Command | `npm install --omit=dev` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |
| Instance type | Free для тестирования, если доступен |

5. В Environment добавьте:

```text
NODE_VERSION=20.18.1
NODE_ENV=production
SEARCH_CACHE_TTL=180
DETAIL_CACHE_TTL=600
MARKET_CACHE_TTL=1200
CATALOG_CACHE_TTL=21600
AV_TAXONOMY_CACHE_TTL=43200
AV_SOURCE_TIMEOUT_MS=14000
SUPABASE_URL=https://ВАШ-PROJECT-REF.supabase.co
SUPABASE_ANON_KEY=ВАШ_PUBLISHABLE_ИЛИ_ANON_KEY
```

6. Включите **Auto-Deploy** для ветки `main`.
7. Нажмите **Create Web Service**.

Blueprint уже содержит эти параметры, поэтому ручной способ нужен только как запасной.

## 8. Как публиковать обновления

После изменения файлов локально:

```bash
git add .
git commit -m "Update MOTOR.BY"
git push origin main
```

Поскольку в `render.yaml` установлено `autoDeploy: true`, Render автоматически запустит новый deploy после push в `main`.

Если файлы меняются через сайт GitHub:

1. откройте нужный файл;
2. нажмите кнопку редактирования;
3. сохраните через **Commit changes** в `main`;
4. дождитесь нового deploy в Render.

Ход обновления виден в Render в разделе **Events** или **Logs** сервиса.

## 9. Проверка на iPhone 13 mini

Интерфейс оптимизирован под CSS-ширину **375 px** и учитывает безопасные зоны экрана.

После деплоя:

1. откройте сайт в Safari на iPhone;
2. обновите страницу без старого кэша;
3. убедитесь, что первой открывается развёрнутая форма и до нажатия **«Показать объявления»** поиск не запускается;
4. выберите марку и модель: карточки поколений должны появиться сразу под полем **«Модель»**; отметьте минимум два поколения и убедитесь, что обе карточки остаются выбранными;
5. выберите коробку **«Автомат + робот»** и после поиска убедитесь, что в выдаче встречаются автоматы и роботы, но не механика;
6. проверьте, что все объявления одного поколения используют одну и ту же каталожную фотографию поколения независимо от площадки;
7. запустите поиск и проверьте, что форма плавно превращается в закреплённую кнопку **«Настройки»** и одну строку из пяти источников;
8. убедитесь, что полноширинная кнопка сортировки заметна и меняет порядок по свежести, цене, году и пробегу;
9. прокрутите объявления, переключите источник в закреплённой строке и снова разверните настройки;
10. проверьте, что каждая карточка имеет белую окантовку, а стрелки переключения находятся точно посередине изображения;
11. проведите пальцем влево и вправо по фотографии карточки, затем повторите свайпы в полноэкранной галерее; счётчик должен переключаться, а обычный вертикальный жест — прокручивать страницу;
12. откройте фотографию: double tap или pinch должен масштабировать только фото, но не страницу; после увеличения один палец должен перемещать фотографию, не перелистывая её, а кнопки управления должны оставаться неподвижными;
13. проверьте портретный и альбомный режимы;
14. проверьте поля формы — Safari не должен увеличивать страницу при фокусе;
15. выберите по очереди источники **«Дилеры»** и **«Автохаусы»** и регион вне Минска: должны появляться подходящие компании AV.BY из выбранного региона;
16. переключите плотность карточек: компактная карточка должна стать короче, но кнопки оригинала и полного блока должны оставаться доступными;
17. сохраните автомобиль сердцем, откройте кнопку **«Избранное»** в шапке, проверьте список и режим полноценных карточек; затем добавьте заметку, сохраните фильтр, закройте/откройте Safari и убедитесь, что данные сохранились;
18. нажмите **Поделиться → На экран Домой**, запустите установленный MOTOR.BY и проверьте standalone-режим;
19. после одного онлайн-запуска временно отключите интернет: должен открыться shell и последняя выдача с явной пометкой офлайн-состояния;
20. проверьте карточки, галерею и нижнюю безопасную зону.

При добавлении сайта на домашний экран используются `manifest.webmanifest`, `apple-touch-icon`, `viewport-fit=cover` и безопасные отступы для выреза и индикатора Home.

## 10. Частые проблемы

### Render пишет, что `render.yaml` не найден

Файл оказался во вложенной папке. Переместите `render.yaml`, `package.json`, `server.js` и `index.html` в корень репозитория.

### Создан Static Site, но поиск не работает

Удалите Static Site и создайте **Web Service** или **Blueprint**. Проекту нужен Node backend для запросов к источникам.

### В логах `Cannot find package.json`

Проверьте Root Directory. Если файлы находятся в корне репозитория, поле должно быть пустым.

### Render не видит приватный репозиторий

В настройках GitHub App для Render предоставьте доступ к `motor-by`, затем обновите список репозиториев в Render.

### Главная открывается, но один источник показывает ошибку

Это не обязательно ошибка деплоя. Внешняя площадка может временно блокировать запросы или изменить формат. Проверьте:

```text
/api/health
```

и статусы источников на главной странице. Другие адаптеры продолжат работать независимо.

### Появляется сообщение о минутном лимите резервного транспорта AV.BY

Такое сообщение относится не к каталогу AV.BY, а к последнему серверному резерву Jina Reader: общий исходящий IP Render был ограничен SafeLine, после чего Reader получил слишком много запросов. Начиная с версии `1.3.5`, интерфейс выполняет поиск и загрузку detail AV.BY напрямую из публичного Android API в браузере посетителя. Reader остаётся только вторичным серверным резервом и при обычной работе сайта не расходуется. Замените файлы проекта актуальной сборкой и выполните новый deploy.

### Объявления AV.BY есть, но фотографии не загружаются

CDN фотографий AV.BY может отвечать кодом `423` на запросы с общих исходящих IP Render, хотя сами изображения остаются публичными. В версии `1.2.2` фотографии с проверенного домена `avcdn.av.by` загружаются напрямую браузером без `Referer`, а старые обращения к `/api/media` перенаправляются на тот же CDN. Замените файлы проекта актуальной сборкой, выполните commit и `git push`; отдельные переменные окружения или API-ключи не нужны.

### После обновления видна предыдущая PWA-версия

Service Worker не прерывает открытую вкладку и активирует новую версию безопасно. Закройте все вкладки MOTOR.BY и откройте сайт снова. Если браузер продолжает показывать старый shell, удалите данные сайта/Service Worker в настройках браузера и перезагрузите страницу онлайн. Не ставьте долгий immutable cache на `sw.js`: сервер этой сборки уже отдаёт его с `no-cache, must-revalidate`.

### После push ничего не обновилось

1. Убедитесь, что push попал в ветку `main`.
2. Откройте Render → сервис → **Settings**.
3. Проверьте, что Auto-Deploy включён для `main`.
4. При необходимости нажмите **Manual Deploy → Deploy latest commit**.

### Сайт долго открывается после паузы

Render Free выключает Web Service после 15 минут без входящих HTTP-запросов. Код внутри уже уснувшего Node-процесса не может разбудить сам себя.

В сборку включена папка `cloudflare-worker/` с готовым Cloudflare Worker. Его Cron Trigger раз в 10 минут обращается к `/api/health`, не запускает тяжёлый поиск и поддерживает входящий трафик до достижения 15-минутного окна Render.

1. Проверьте `RENDER_HEALTH_URL` в `cloudflare-worker/wrangler.toml`.
2. Откройте терминал в этой папке.
3. Выполните:

   ```bash
   npx wrangler login
   npx wrangler deploy
   ```

4. Подождите до 15 минут, затем откройте Cloudflare → Workers & Pages → `motor-by-keep-awake` → **Settings → Triggers**. Там должен быть Cron `*/10 * * * *`.
5. Для просмотра результатов используйте `npx wrangler tail` или Cloudflare → **Cron Events**.

Worker использует всего 144 запуска в сутки и не требует API-ключа MOTOR.BY. Это практичный бесплатный вариант, но не гарантия uptime: отдельный cron может задержаться, Render может перезапустить Free-инстанс, а постоянно работающий сервис расходует почти все 750 Free instance hours в месяц. Для гарантированной работы без сна переключите Render на платный Starter или выше.

Полная инструкция и локальная проверка находятся в `cloudflare-worker/README.md`.
